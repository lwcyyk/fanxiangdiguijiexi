# 域名中心一页纸安装卡

> 适用范围：域名中心离线安装包；R1 为第一跳，R2/R3 为上游解析器。
>
> 核心原则：先核对人、机、包，再安装；先 Shadow，后切流；任何门禁失败都停止，不能绕过。

## 一、安装前必须拿到的材料

- 经批准的站点清单、变更单号、安装窗口和回滚负责人；
- 离线安装归档及其 `SHA256SUMS`、发布清单和固定的源代码 commit；
- 所有容器镜像的完整 `name@sha256:<64 位十六进制>` 引用和离线镜像归档；
- 每台主机各自的证书、Agent 私钥及 Wrapper/Trace/peer Token；
- R1/R2/R3 的真实主机名、管理地址、Resolver 地址和期望角色；
- 已批准的 Shadow 测试域名、VIP 切换方式和回滚 RTO。

不得使用 `latest`、仅带 tag 的镜像、示例 IP、占位证书或共享秘密。安装机无需互联网；安装期间不要临时开通公网。

## 二、五分钟核对

1. **核人**：实施人和复核人同时在场，变更单处于可执行状态。
2. **核机**：屏幕显示的实际主机名必须等于安装包中的 `expected_host`；角色必须匹配。
3. **核包**：离线执行 SHA-256 校验；校验失败立即隔离该介质。
4. **核磁盘与 Docker**：空间足够，Docker/Compose 可用，时间同步正常。
5. **核端口**：R1 Shadow 监听 UDP/TCP `1053`；R2/R3 不得出现 Wrapper 服务、容器、profile、端口或环境变量。

## 三、按向导安装

在解压后的安装包根目录运行包内向导；使用包内 `--help` 显示的命令和参数，不从网络下载脚本。向导应依次完成：

1. 校验归档、清单、镜像 digest 和目标主机；
2. 只从离线归档载入镜像，并核对载入后的 RepoDigest；
3. 备份现有 Resolver 配置，不删除数据目录；
4. 启动 Registry Sync，等待真实 readiness；
5. 启动 Agent、Trace Adapter 和 Resolver，等待 Socket/readiness；
6. **仅 R1** 启动 Wrapper Shadow `1053/udp` 与 `1053/tcp`；
7. 写入安装状态和脱敏证据。

中断后重新运行同一向导。它必须从最后一个成功步骤继续；已经完成且输入未变化的步骤显示“已完成/跳过”，不得重复生成密钥、重复破坏配置或清空数据。

## 四、现场验收

- R1：`1053/udp`、`1053/tcp` Shadow 均通过；真实客户端 `53` 端口尚未切换；
- R2/R3：结构上不存在 Wrapper，而不只是“暂时未启动”；
- Trace、Agent、Registry、证书、Token 或上游异常时失败关闭并返回 `SERVFAIL`；
- SQLite `PRAGMA integrity_check` 为 `ok`；
- 安装证据中每个检查只有 `passed`、`failed`、`blocked` 或 `not_run`，且有中文说明；
- `blocked` 必须写明缺少的外部材料；前置失败后的项目必须是 `not_run`，不能伪写 `passed`。

## 五、何时绝对不能切流

存在任一情况就保持 Shadow 或回滚：主机不匹配、摘要不匹配、移动镜像标签、R2/R3 含 Wrapper、真实 Resolver Trace 缺失、身份/Root/Endpoint 未发布、网络隔离未验收、负向测试失败、证书/Token 不合格、容量或回滚 RTO 未达标。

这些外部条件不能由离线安装器自动完成。安装包构建成功或本机安装成功，不等于真实服务器部署完成，更不等于生产流量已启用。

## 六、故障与支持

先停止切流，不执行 `docker compose down -v`，不要删除安装状态。运行包内支持信息采集功能，复核输出后再导出。支持包只能包含版本、摘要、步骤状态和脱敏日志；不得包含私钥、Token、密码、带凭据 URL、完整环境文件或 Registry/RPC API key。

回滚只把 DNS 入口切回原 Resolver，并按手册恢复原配置；不通过关闭验证来维持 Wrapper 在线。

## 七、提交验收证据（发布负责人）

在固定 Source Commit 执行（`--allow-blocked` 只保留外部 `blocked/not_run`，不表示通过）：

```sh
SOURCE_COMMIT=$(git rev-parse HEAD)
python3 tools/finalize_domain_center_easy_install.py finalize --source-commit "$SOURCE_COMMIT" --delivery /绝对路径/resolver-identity-domain-center-easy-install-<version> --output specs/domain-center-easy-install/test-summary.json --allow-blocked
git add specs/domain-center-easy-install/test-summary.json
test ! -d artifacts/domain-center || git add artifacts/domain-center/
git -c user.name='LWC' -c user.email='lwc@users.noreply.github.com' commit -m 'test(installer): record domain-center delivery evidence'
EVIDENCE_COMMIT=$(git rev-parse HEAD)
python3 tools/finalize_domain_center_easy_install.py verify-evidence-diff --source-commit "$SOURCE_COMMIT" --evidence-commit "$EVIDENCE_COMMIT"
```

Evidence Commit 只允许专用证据路径；真实主机、Trace、PKI、网络隔离、监控、备份、容量、回滚与切流审批未完成时，必须保持 `real_server_deployed=false`、`production_traffic_enabled=false`。
