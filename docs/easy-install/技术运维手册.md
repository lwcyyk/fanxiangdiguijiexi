# 域名中心技术运维手册

## 1. 运维目标和不可越过的边界

本手册面向平台、DNS、安全和现场运维人员，覆盖离线制品、安装状态、运行检查、证据、升级回滚和支持信息采集。

安装器是失败关闭的本地执行器，不是基础设施编排平台。下列事项属于外部要求，必须由责任系统或责任人提供真实证据：

- 真实 R1/R2/R3 主机、网络区、VIP、堡垒机、防火墙和监控；
- 独立 Agent/TLS 私钥、用途隔离 Token、可信 CA 和证书生命周期；
- Registry/Norn 的真实 Root、identity、Endpoint、角色和只读访问；
- Knot Resolver 真实内部 Trace 生产者、Socket 权限和版本；
- 备份存储、告警接收人、容量目标、观察窗口、切流审批与回滚 RTO。

缺失项必须进入证据的 `blocked`，依赖它的未执行项进入 `not_run`。不能用示例 IP、Mock RPC、fake Docker/host probe、合成 Trace 或临时公网服务把状态改成 `passed`。

## 2. 制品与供应链控制

### 2.1 可接受输入

- 站点归档必须来自批准的固定 40 位 commit；
- 每个 OCI 镜像引用必须是 `repository@sha256:<64 hex>`；
- 离线镜像归档、包内文件和发布级文件均有 SHA-256；
- 同一输入重复构建得到逐字节相同的归档；tar 路径、顺序、mtime、uid/gid、用户名/组名及 gzip 头都固定；
- Inventory 使用拒绝重复 key 的解析器，并校验主机 ID、角色、端口、数据目录、Socket、key ID 和 secret profile 唯一性。

禁止项包括：`latest`、仅 tag、短 digest、归档摘要与 OCI digest 混淆、凭据 URL、绝对/越界归档路径、危险链接和设备节点。载入离线镜像后必须用 Docker inspect 得到的 RepoDigest 与清单复核，不允许 pull。

### 2.2 角色不变量

| 主机角色 | Wrapper | DNS 暴露 | 必需组件 |
| --- | --- | --- | --- |
| R1 / `first-hop` | 必须存在 | Shadow UDP/TCP 1053；批准后才切 53 | Sync、Agent、Trace、Resolver、Wrapper、独立 SQLite |
| R2/R3 / `upstream` | **结构上不存在** | 仅经批准的上游 Resolver 端口 | Sync、Agent、Trace、Resolver、独立 SQLite |

“结构上不存在”要求归档文件、Compose、profile、环境变量、端口映射和容器清单均不含 Wrapper。禁止通过 `replicas: 0`、不启动 profile 或防火墙隐藏一个实际存在的 Wrapper。

## 3. 安装状态机

建议将安装状态保存在安装根目录外的受保护状态目录，权限最小化，并使用临时文件 + `fsync` + 原子替换写入。状态至少绑定：站点/主机 ID、`expected_host`、角色、发布版本、commit、manifest digest 和每一步输入 digest。

```text
validated
  -> images_loaded
  -> config_backed_up
  -> registry_ready
  -> agent_trace_ready
  -> resolver_ready
  -> wrapper_shadow_ready（仅 R1）
  -> evidence_written
```

每步只在探针真实成功后标记完成。进程退出、主机重启或写盘中断后，下一次运行从最后一个已验证步骤继续。恢复时重新验证已完成步骤的不变量；状态与当前包/主机不匹配必须退出，不得跨主机复制状态。

幂等要求：

- 相同包重复执行结果不变；
- 已有数据和外部秘密不被覆盖或删除；
- Resolver 原配置只创建一次可验证备份；
- 已载入的相同 digest 不重复 pull；
- 阶段失败只回退激活指针/配置入口，不回滚或清空 SQLite、链状态、Trace spool；
- 清数据操作必须独立、显式且验证所有权标记，不能是普通卸载的一部分。

## 4. 主机和 Docker 探针

安装前在任何有副作用的步骤之前比较实际 hostname 与包内 `expected_host`。比较规则由清单明确，默认使用完整规范名精确匹配；不能只比较前缀或忽略域后缀。失败证据记录预期值、经过脱敏的实际值、时间和步骤，不记录秘密。

Docker 探针需要区分：

1. Docker daemon/Compose 可用；
2. 镜像归档 SHA-256 正确；
3. `docker load` 成功；
4. 本地镜像含期望 RepoDigest；
5. Compose 渲染没有隐式 pull、移动 tag 或角色越界；
6. 进程健康和应用 readiness 成功。

单元测试必须以 fake Docker/host probe 注入结果，不访问网络、不依赖本机 Docker。fake 结果只验证状态机和命令边界；现场验收仍使用真实探针。

## 5. 启动、健康与日常检查

严格按 `Registry Sync → Agent/Trace Adapter → Resolver Trace → Wrapper（仅 R1）` 启动。每层等待应用 readiness，不能把容器运行状态当作就绪。

每日/每班至少检查：

- Registry finalized 高度、快照新鲜度和双只读端点差异；
- Agent/Wrapper readiness、mTLS 到期时间和 Token 拒绝计数；
- Trace Socket 所有者/权限、pending、spool、dead-letter 和关联失败；
- SQLite `integrity_check`、WAL 大小、备份新鲜度；
- Wrapper accepted/SERVFAIL/overload、上游及验证延迟；
- Docker 重启、日志轮转、磁盘、inode、FD、CPU、内存和时间同步；
- R2/R3 容器与端口中仍然不存在 Wrapper。

Agent/Wrapper 不得拥有 Registry/Norn 写权限。跨独立链路的 Resolver、Agent、SQLite、metrics 和秘密默认拒绝；peer Token 只在同一实际 DNS 链相邻节点间使用。

## 6. 证据模型

每个检查都必须有机器状态和中文条目：

- `passed` / `通过`：真实执行并满足要求；
- `failed` / `失败`：真实执行但不满足要求；
- `blocked` / `阻断`：缺少外部输入、权限、审批或系统；
- `not_run` / `未运行`：由于前置失败/阻断或明确不适用而没有执行。

证据记录检查 ID、状态、`status_zh`、`message_zh`/`reason_zh`、时间、主机/角色、输入摘要和非秘密输出摘要。若前置项 `failed` 或 `blocked`，后续项不能写 `passed`，应显式写 `not_run` 并引用前置检查 ID。聚合状态不能把 `blocked`/`not_run` 计入通过率，也不能把“包已生成”推导成 `real_server_deployed=true` 或 `production_traffic_enabled=true`。

建议的外部阻断项至少包括：

- 真实 Resolver Trace 未交付；
- Root/identity/Endpoint 未发布或未 finalized 核验；
- 现场 PKI/秘密未交付；
- 防火墙、监控、备份、容量、回滚演练未验收；
- Shadow/正式切流尚未审批。

## 7. Shadow 与切流

R1 Shadow 固定使用批准地址上的 UDP/TCP `1053`，避免抢占现网 `53`。R2/R3 不监听 Wrapper 端口。Shadow 覆盖 UDP/TCP、冷/热缓存、真实 R1→R2、重启续传、SQLite reconcile 和全套失败关闭。

只有以下条件全部有真实 `passed` 证据时才能切流：供应链校验、主机/角色、真实 Trace、Registry/identity/Endpoint、mTLS/Token、跨链路隔离、负向测试、监控告警、备份恢复、容量和回滚 RTO。按变更单逐级放量并持续观察，任何门限触发立即回滚入口。

## 8. 升级、恢复和回滚

升级前保存当前发布指针、原 Resolver 配置备份、数据库在线备份和脱敏证据。新版本使用新的不可变发布目录，健康检查通过后才原子切换激活指针。失败时恢复上一指针和 DNS 入口，不删除当前数据。

恢复演练在隔离目录执行，先校验 SHA-256，再运行 SQLite `PRAGMA integrity_check`，不能覆盖在线库。普通卸载保留发布、状态和数据；生产主机不得运行 `docker compose down -v`。

回滚顺序：停止放量 → VIP/入口切回旧 Resolver → 等待新 Wrapper 排空 → 停止 Wrapper → 保全状态和证据 → 分析。不得通过关闭证据验证继续让 Wrapper 承载流量。

## 9. 支持包与秘密脱敏

支持包默认拒绝未知文件，只允许白名单字段：版本、commit、manifest/file digest、主机角色、步骤状态、容器健康摘要、资源指标和脱敏错误。下列内容不得收集：

- Agent/TLS/issuer/治理私钥；
- Wrapper、Trace、peer Token、密码、Cookie、Authorization 头；
- `.env` 全文、secret 目录、数据库/WAL 原文件；
- 含用户名、密码、API key 或 query credential 的 URL；
- 证书私钥、Docker registry 登录配置和 shell history。

脱敏必须覆盖大小写不同的字段名、JSON/YAML/环境变量、`Bearer`/Basic 头、URL userinfo 与常见 query 参数。输出前再次扫描私钥 PEM 标记、JWT/Token 模式、凭据 URL 和清单中已知秘密值；发现命中时支持包生成失败，而不是仅警告。支持包本身按敏感运维制品加密传输、限时保存和审计访问。

## 10. 事故处理速查

| 现象 | 立即动作 | 禁止动作 |
| --- | --- | --- |
| expected host 不匹配 | 停止，核对包与变更单 | 改 hostname 或复制状态绕过 |
| 镜像/文件摘要不匹配 | 隔离介质，重新交接 | pull 或继续启动 |
| Trace/Registry/Agent 异常 | 停止放量，保持失败关闭 | 关闭验证放行原响应 |
| R2/R3 出现 Wrapper | 停止该主机，判定包角色违规 | 仅停止容器后继续验收 |
| 状态文件损坏 | 保全现场，从原子备份/证据恢复 | 删除数据目录后重装 |
| 秘密进入日志/支持包 | 停止传播、撤销轮换、审计访问 | 仅删除本地副本即结案 |
| Shadow 指标超阈值 | 保持现网入口，采集脱敏证据 | 继续扩大切流 |

事件关闭前记录真实状态与未执行项。只要真实服务器、真实 Trace、网络隔离或生产审批仍缺失，结论就必须保持“阻断/未运行”，不能表述为完整生产部署。

## 11. Source Commit 与 Evidence Commit 收口

以下命令中的 40 位哈希必须逐字使用，不接受分支名、短哈希或“当前最新”替代。先在业务源码冻结的 Source Commit 生成并验证离线交付；此步骤不会部署真实服务器，也不会切换生产流量：

```sh
SOURCE_COMMIT=$(git rev-parse HEAD)
git cat-file -e "${SOURCE_COMMIT}^{commit}"
python3 tools/finalize_domain_center_easy_install.py finalize \
  --source-commit "$SOURCE_COMMIT" \
  --delivery /绝对路径/resolver-identity-domain-center-easy-install-<version> \
  --output specs/domain-center-easy-install/test-summary.json \
  --allow-blocked
```

`--allow-blocked` 只表示允许把结构正确但外部条件未完成的交付记录为 `blocked`/`not_run`；它不把这些状态视为通过。真实 Ubuntu 22.04/24.04 主机、真实 OCI 运行、Resolver Trace、PKI/identity、网络隔离、负向失败关闭、监控、备份恢复、容量、回滚 RTO 和切流审批仍须外部真实证据。

复核生成的机器摘要与脱敏结果后，只提交专用证据路径，得到 Evidence Commit：

```sh
git add specs/domain-center-easy-install/test-summary.json
test ! -d artifacts/domain-center || git add artifacts/domain-center/
git -c user.name='LWC' -c user.email='lwc@users.noreply.github.com' commit -m 'test(installer): record domain-center delivery evidence'
EVIDENCE_COMMIT=$(git rev-parse HEAD)
python3 tools/finalize_domain_center_easy_install.py verify-evidence-diff \
  --source-commit "$SOURCE_COMMIT" \
  --evidence-commit "$EVIDENCE_COMMIT"
```

Evidence Commit 相对 Source Commit 只能修改 `specs/domain-center-easy-install/` 和 `artifacts/domain-center/`。任何源码、配置、脚本或其他规格路径变化都会被拒绝；摘要必须精确绑定 Source Commit 和交付根 `证据.json` 的 SHA-256。当前交付阶段应继续保持 `real_server_deployed=false`、`production_traffic_enabled=false`。
