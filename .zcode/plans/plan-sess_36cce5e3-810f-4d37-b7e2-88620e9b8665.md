## 当前阻塞点

RC13 六个运行时二进制已经部署到 R3、R2、R1 和 Auth DNS，二进制摘要与可复现构建结果一致。真实实验已经证明：

- 完整递归 miss 可以在 `controlled-strict` 下生成并持久化成功的 Evidence Graph；
- 后续缓存命中仍失败；
- 直接原因不是缓存溯源查询逻辑本身，而是 Norn Registry 每次同步都从很早的发布区块反向扫描，单轮通常超过 45 秒；四个节点的 heartbeat 无法稳定同时保持新鲜，逐跳验证因此随机在 R1/R2/R3/Auth DNS 处 fail-close。

不能通过放宽 45 秒或绕过链上包含性验证解决。RC13 已部署，后续修复使用新的 `0.3.0-norn-knot-rc14`，不覆盖 RC13。

## 实施计划

1. **实现 Norn 已验证发布的进程内增量缓存**
   - 在 `rust/crates/ri-chain-adapter/src/norn.rs` 的 `NornRegistryAdapter` 增加私有、非持久化的已验证发布状态。
   - 首次启动仍执行当前完整、双节点一致的 bounded reverse scan，确认最新 finalized Registry 命令确实是匹配当前值的 `set`。
   - 后续当前 Registry 原始值不变时：重新校验缓存的发布区块和已验证 horizon 区块哈希；只扫描上次 horizon 之后新 finalized 区块；若没有新 Registry 命令则沿用已验证发布；若有新命令只接受最新命令为匹配值的 `set`。任何不同值、非 `set`、双节点分歧、回滚或哈希变化均 fail-close。
   - Registry 原始值变化、增量间隔越界或缓存失效时，回退到现有完整扫描。
   - 缓存只存在于进程内；重启必须重新完整验证。
   - 每轮仍重新执行 finalized head、双节点 contract value agreement、snapshot 签名/有效期/checkpoint/state root、身份文件与端点绑定等全部验证。

2. **补齐聚焦回归测试**
   - 抽取仅在 `norn.rs` 内部使用的小型扫描 helper，使合成 `Block` 能测试算法，不改变公共 `RegistryChainAdapter` 接口，也不建设完整 gRPC mock 平台。
   - 覆盖冷启动完整扫描、缺失发布失败、unchanged value 只扫描新增区块、新匹配发布推进缓存、新的不匹配/非 `set` 失败、`V -> X -> V` 最新命令语义、哈希变化/高度回退/节点分歧/扫描失败不推进缓存、重启无快捷路径。
   - 保留 `ri-registry-sync` 现有 heartbeat 成功/失败测试。

3. **RC14 质量门和可复现构建**
   - 工作区版本提升为 RC14，准确记录 source commit 与 dirty diff。
   - 运行 fmt、聚焦测试、workspace test、clippy `-D warnings`。
   - 使用固定 Rust 1.97 Bookworm builder、locked/offline 输入和两个独立 clean target 构建，要求六个二进制 A/B SHA-256 一致。
   - 从 RC13 OCI 派生 RC14 OCI 两次，要求 layer/config/manifest/archive 字节级一致并更新证据。

4. **只升级需要修复的服务**
   - 功能上只需升级 R3、R2、R1、Auth DNS 的 `registry-sync`；不重启 Resolver、Agent、Wrapper、Trace Adapter、Producer、Authority Proxy、Norn 或 Management。
   - 保持 `controlled-strict` 和 45 秒 freshness。
   - 验证首次冷扫描后，连续多个周期 heartbeat age 稳定低于 45 秒，且现有 DB、Evidence、cache、dead-letter 保留。

5. **恢复真实 Cache Provenance 实验**
   - 不清除现有缓存；继续使用当前独立实验缓存目录。
   - 用唯一名称产生真实 miss，要求完整递归、成功 Evidence Graph、持久化 graph digest。
   - 第二次查询要求 CacheHit 自动写入真实 `source_graph_digest`，由 Agent 重新验证来源 Graph，Wrapper 返回原始 DNSSEC 响应。
   - 从 R1 SQLite 证明 source graph/cache object/generation 绑定和跨 query-digest 成功；再验证错误 digest、不存在来源、不同 cache object、旧无 provenance 均 fail-close。

6. **完整实验和傻瓜式安装包**
   - provenance 通过后执行 A/AAAA/TXT UDP/TCP、AD/RRSIG、逐跳链路、顺序/并发和组件停止/恢复实验。
   - 不执行任何防火墙、密码、密钥或 PKI 操作。
   - 全部实验通过后制作简单离线 Docker 包：镜像、Compose、配置模板、`install.sh`、`check.sh`、短 README；只做本机加载、启动、readiness 和 DNS 验证，不扩展生命周期平台。

在真实 miss→verified hit 和完整实验通过前保持：`cache_hit_path_passed=false`、`trace_binding_passed=false`、`trace_binding_known_p0=true`、`release_ready=false`、`production_capacity_validated=false`、`production_deployed=false`。
