# 阶段 1：RC15 Cache Provenance 根源修复

## 已确认根因

当前 `ri-trace-adapter` 对每个没有 `source_graph_digest` 的 CacheHit 调用 `find_cache_source_graph(cache_object_digest, None)`（`rust/crates/ri-trace-adapter/src/main.rs:223-288`）。该 SQL 在 `rust/crates/ri-store/src/lib.rs:712-748`：

- 接受所有已被 Wrapper claim、且 terminal `CLIENT_RESPONSE.cache_object_digest` 相同的 Graph；
- 不区分原始 miss Graph 与派生 CacheHit Graph；
- `ORDER BY g.rowid DESC LIMIT 1` 会选择最新派生 Graph。

因此实际形成 `G1→G0, G2→G1, G3→G2`。Agent 随后把派生 digest 当 source pin 再做同一 selector；重启后该 pin 不能稳定解析为 canonical root，触发 `cache-hit source graph is absent from the current Registry generation`。

另一个独立问题是 DB 列 `ri_v2_evidence_graphs.snapshot_generation` 保存内部 `cache_generation`（`put_graph`, `rust/crates/ri-store/src/lib.rs:619-646`），而 Graph 内 Registry reference 使用链上 `snapshot_generation`。二者本来是两个不同概念；当前查询和错误文案混称 Registry generation，导致 generation 变化时历史真实 Graph被错误排除。

## 最小兼容修复

不新增数据库字段，利用现有 Graph schema：原始 miss Graph 的 `cache_provenance=None`；派生 Hit Graph 的 `cache_provenance=Some(...)`。

1. 在 `ri-store` 将 source selector 定义为 canonical root selector：
   - 必须是已 claim 的 terminal `CLIENT_RESPONSE`；
   - cache object、Graph/event query/response digest 严格一致；
   - 必须 `json_extract(g.graph_json,'$.cache_provenance') IS NULL`；
   - 必须是成功、无 Graph errors、至少含一个身份节点；
   - pinned digest 必须精确匹配；
   - 不再要求历史 Graph 的内部 `snapshot_generation == 当前 cache_generation`。
2. 未 pin 时选择最早的合法 original miss root（稳定排序 `g.rowid ASC`），从而永远返回 G0；pin 时只允许 G0，派生 G1/G2 digest 必须拒绝。
3. Trace Adapter enrichment 永远写入 canonical G0 digest，重启后从 SQLite 重算仍得到同一 G0。
4. Agent 对 G0 做历史真实性验证：canonical object hash、Graph/identity/edge/attestation 签名、完整 lineage、cache object 绑定、DNSSEC policy。
5. 将“当前状态验证”从“Graph 内 generation 必须等于当前 generation”改为逐节点查询当前本地 Registry：
   - server ID 必须仍存在；
   - identity/object hash、endpoint 和 agent key 必须与历史 Graph 身份相符；
   - current resolver/root status 必须 ACTIVE，endpoint binding MATCHED；
   - 当前 heartbeat 必须新鲜；
   - generation 可增加但语义未变时允许；撤销、替换身份、endpoint/key 改变时拒绝。
6. 递归验证 `terminal_cache_graphs`，加入 visited digest set 和深度/节点数上限，明确拒绝循环、自引用、缺失 root、错误 digest。
7. 保留 legacy cache 在 ControlledStrict 下 fail-close。
8. 改正错误文案，区分 storage cache generation、链上 snapshot generation、当前身份失效和 canonical root 缺失。

## 测试

在 `ri-store/tests/store.rs`、`ri-agent/tests/agent_service.rs`、`ri-trace-adapter/src/main.rs` 测试中覆盖用户列出的 A–L：

- MISS→Hit→Hit→Hit 都 pin G0；
- Agent、Trace Adapter、Registry Sync 模拟重启后 Hit；
- storage generation 增加但 Registry 语义相同仍成功；
- 当前身份撤销/替换/endpoint 或 key 改变拒绝；
- 缺失、错误 digest、错误 cache object、派生 Graph pin、循环 provenance 拒绝；
- 并发相同 cache object 不串 root；
- legacy cache 严格拒绝。

若不新增列则无需 schema migration；现有 RC14 数据在 RC15 首次 Hit 时会由新 selector 自动回到原始 miss G0。

# 阶段 3：严格 Trace Binding P0（后续 RC）

## 最小安全架构

现有 Knot hook BEGIN 只有 `(pid, request_uid, DNS wire)`，没有客户端 socket tuple；SEND 只有目标 endpoint。仅靠当前 hook无法安全完成用户要求的源 tuple + one-time authenticated intent。因此需要最小新增两部分，而不是伪造通过：

1. **Agent mTLS Context API 与持久化 context store**
   - 新增预注册/消费 API，复用现有 Agent mTLS、peer principal 和 directional credential体系；不使用 bearer 万能 token。
   - context 字段：`root_request_context_id`、`context_id`、`parent_context_id`、parent/subject identity、query digest、transport、source/destination endpoint、DNS transaction ID、随机 child nonce、issued/expires、single-use status、签名/MAC。
   - SQLite 新表保存未消费/已消费上下文，唯一约束和原子 consume；schema 向后迁移。
2. **Knot trace hook最小扩展**
   - 在 BEGIN 暴露真实入站 peer/local tuple；在 SEND 暴露真实本地 ephemeral source tuple和目标 tuple（若 Knot API在发送前尚无已绑定 socket，则在实际 socket建立/发送点增加 hook，而不是猜测端口）。
   - Hook 协议升级并保持显式版本；Trace Producer只在唯一匹配、未消费 context存在时创建 Trace，否则让 Knot fail-close。

## 逐跳流程

- Wrapper 在发 DNS 前生成 128-bit以上 `root_request_context_id`，通过 mTLS 向 R1 Agent注册 root intent；R1 Producer BEGIN用实际 packet+tuple原子消费。
- 每次 R1 SEND 前，R1 Agent依据 root生成随机 child context并通过 mTLS注册到 R2；R2 BEGIN消费。R2→R3、R3→Authority同理。
- Authority Proxy作为可控入口，在处理 DNS前用真实 peer/local tuple向本地 Agent消费 context；没有唯一 context即 SERVFAIL。
- 对 retry 每次生成新的 child nonce/context；旧 context不可复用。
- TraceEvent、TargetAttestation、ServerHopEvidence、QueryEvidenceGraph增加 `root_request_context_id` 和 per-hop context binding；Wrapper最终要求 Graph root ID等于 pending root ID并一次性完成。
- context先到无DNS由TTL清理；DNS先到无context、伪造、重复、过期、peer/tuple/query不匹配全部 fail-close。

如果实际 Knot socket API无法在 SEND 时获得本地 ephemeral port，将把 outbound DNS I/O移到一个最小受控本机 egress proxy（Knot只连 proxy，proxy负责预注册 context并用其真实 socket tuple发送），而不是退回时间窗口匹配。

## Trace Binding测试

实现用户列出的17类攻击：相同 query并发、相同 transaction ID、回绕、UDP duplicate/delay、retry、完全相同 bytes、source port复用、伪造/replay/未到/重复消费、重启、高并发、TCP复用、UDP/TCP并发。要求 `false_accept=0`、`cross_trace_binding=0`、`replay_accept=0` 才可置 `trace_binding_passed=true`。
