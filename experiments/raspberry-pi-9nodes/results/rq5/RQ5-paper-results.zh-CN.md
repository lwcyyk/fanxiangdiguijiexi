# RQ5：完整递归路径上的性能与可靠性

以下正文对应完成后的 26 条件数据集，供论文结果、方法与局限段落插入使用；不代表整篇论文或完整安全审计已完成。配套完整表见 `condition_tables.md`，英文版本见 `RQ5-paper-results.en.md`。

## 可插入论文的方法段落

本研究在九节点物理测试平台上比较匹配的原生递归模式（B0-matched）、认证串行模式（B1-serial）与认证流水线模式（B1-pipelined）。正式实验包含 26 个条件，每个条件执行 5 对相邻模式 block，共 130 对、260 个 block。其中，22 个条件比较 B0-matched 与 B1-pipelined，另外 4 个条件在 D3 下比较 B1-serial 与 B1-pipelined。条件覆盖 UDP/TCP、hot/cold/mix/NXDOMAIN、D3 大应答 near 与 UDP 截断后 TCP fallback，以及 UDP hot/cold 的 D1–D3 深度变化和 D3 下 0.25、0.5、1、2 QPS 的投放速率变化。mix 工作负载按冻结序列采用 80% hot 与 20% cold。A/B 顺序按条件与重复序号确定性交替，各条件采用 3/2 或 2/3 的 AB/BA 分配，总计 AB=65、BA=65；该设计是平衡顺序而非随机化。

每个 block 包含 60 s 预热、120 s 固定投放测量窗口及额外 180 s 固定 drain。测量窗口分别投放 30、60、120 或 240 次请求，正式数据共包含 30,600 次测量请求及另行统计的 15,300 次预热请求。模式之间独立重置或准备缓存。cold 测量名称在 block 内不重复，并与预热名称集合分离；hot/mix 在冻结序列开始前完成独立成功 prime。D3 保留 R1→R2→R3→权威服务器的完整配置路径，未缓存成功请求依据真实 wire 检查路径；hot 命中按缓存语义允许提前终止，不要求每次重新遍历三个递归节点。每个配对使用相同冻结投放序列，保留客户端、管理节点、R1、R2、R3 与权威服务器六角色原始采集。

主要结果以全部投放请求为分母计算语义正确应答比例，正确 NXDOMAIN 计为成功，SERVFAIL 和超时计为失败。成功应答时延从客户端单次交换任务开始至终止计时，包含 TCP fallback 交换，但不包含冻结投放时刻至任务实际开始的调度滞后。时延 P50 为样本中位数，P95/P99 使用 nearest-rank 分位数。本文表中的时延是各 block 成功应答分位数的中位数，而非合并请求分位数。配对时延比定义为两模式 block 分位数比值的几何平均，零成功 block 的成功条件时延保持未定义。统计单位为配对 block 重复，而不是请求。分析方案在采集完成及初步回执检查后确定，属于事后探索性分析；附带区间为条件内精确经验配对 bootstrap 的 2.5–97.5 百分位，仅描述该平台重复之间的重采样变异。

## 可插入论文的结果段落

### 原生与认证模式的时延差异

在 D3、1 QPS 下，认证流水线原型相对匹配原生模式呈现较大的成功应答时延开销。UDP hot 的 block P50 中位数为 31.69 ms（原生）与 210.29 ms（认证流水线），P95 分别为 93.31 与 511.75 ms。UDP cold 的对应 P50 为 101.93 与 919.74 ms，P95 为 166.38 与 1,463.52 ms。TCP hot 的 P50 为 39.78 与 239.85 ms，TCP cold 为 106.58 与 964.31 ms。四个条件的配对 P50 比值（流水线/原生）分别为 6.99、9.17、5.95、9.08。上述结果刻画该测试平台上整条原型执行路径的开销，不将其单独归因于密码学、TLS、账本操作或某一递归跳。

UDP cold 的成功应答时延随配置递归深度变化。D1、D2、D3 的原生 block P50 中位数为 51.28、72.94、101.93 ms，流水线模式为 355.43、635.35、919.74 ms。相同深度下，流水线 UDP hot 的 P50 为 199.68、201.45、210.29 ms。该结果描述已测试深度之间的端到端差异，不构成对独立单跳成本或一般扩展规律的因果估计。D3 速率扫描中，在 2 QPS cold 条件下，两模式均获得 1,197/1,200 次正确测量应答，原生与流水线的 block P50 中位数分别为 90.99 与 1,241.50 ms。0.25–2 QPS 的扫描没有识别系统饱和点，因此不能据此报告最大吞吐能力。

### 流水线相对认证串行的变化

流水线与认证串行之间的差异较小，且并非所有条件都呈现时延降低。UDP hot 的配对 P50 比值为 1.071，经验重采样区间为 [0.992, 1.198]，其点估计对应约 7.1% 更高的流水线时延。UDP cold、TCP hot 与 TCP cold 的配对比值分别为 0.967 [0.935, 1.001]、0.976 [0.957, 0.997] 与 0.974 [0.948, 1.000]，点估计对应约 3.3%、2.4% 与 2.6% 的较低时延。这些配对估计不同于分别计算的两组中位数之比。例如，UDP hot 的两组 block P50 中位数为 200.29 与 199.69 ms，但几何平均配对比值仍大于 1。尾部指标也未呈现一致收益：TCP cold 的串行与流水线 block P95 中位数分别为 1,609.91 与 1,765.29 ms。每条件仅有 5 对重复，确定性顺序不支持随机化因果检验，本文不作条件级显著改善的结论。

### 可靠性与失败样本

按各模式所参与条件进行描述性汇总，B0-matched 获得 12,897/12,900 次正确测量应答，B1-serial 为 2,398/2,400，B1-pipelined 为 15,172/15,300。这三项汇总的条件组成不同，不是三个模式之间可直接比较的总体效应。测量阶段共保留 133 次失败，其中原生模式有 3 次超时，认证串行有 1 次超时及 1 次 SERVFAIL，认证流水线有 6 次超时及 122 次 SERVFAIL；预热阶段另有 330 次失败。

流水线失败集中于一个 D3 UDP near 大应答 block（pair044）：120 次测量均为 SERVFAIL。该 block 仍计入可靠性分析，使 near 条件的流水线正确应答比例为 480/600（80%），原生为 600/600（100%）。该 block 的成功条件 P50/P95 未定义，near 的配对时延分析因此只有 4 对，不能把剩余成功请求的时延解释为整个条件的可靠服务表现。D3 UDP fallback 条件下，原生与流水线分别获得 600/600 与 599/600 次正确应答，其 block P50 中位数为 191.83 与 1,662.39 ms，P95 为 312.74 与 4,766.33 ms。UDP/TCP NXDOMAIN 条件两模式均为 600/600 正确否定应答。有效最终 block 内的失败与否定应答均依据真实 wire 保留，不用补跑或删除这些失败来提高成功率。

## 可插入论文的局限段落

这些结果来自单一物理平台，每条件只有 5 对重复。条件按时间顺序执行，控制器与输入经历版本化修复，AB/BA 顺序虽平衡但未随机化，不能完全消除时间、缓存准备及环境变化的混杂。另有 7 个启动、采集或路径/缓存核验失败的执行目录未纳入有效正式样本，其原始证据保留，其中有效前缀仅按最终归档计入一次；因此本分析的可靠性分母限于有效最终 block，而不是所有历史执行尝试。采集记录还保留欠压/降频标志 `0x50005`，本研究不主张供电稳定，也不能将时延差异完全归因于协议设计。成功条件时延存在选择偏差，尤其是 near 的零成功 block，必须与全部投放请求的可靠性结果共同解释。经验 bootstrap 区间不能作为小样本总体覆盖保证，全部成功条件的退化成功率差区间也不证明等价性。

原始证据经 13 个最终归档及 176,385 个成员的字节大小与 SHA-256 一致性核对，并重放客户端 wire、计数与时延统计。17,570 次成功测量 B1 应答具有归档内原有的基本身份执行绑定；这些检查不等于深度 GC、因果证明或故障套件审计，其状态仍为 `DEFERRED_NOT_PASS`。资源记录仅包括预热、测量与 drain 前后的主机 loadavg/可用内存快照，未采集进程 CPU/RSS 时间序列、隔离阶段成本或每查询额外控制面字节。P99 可作为附表观察量，但低速条件每 block 仅 30 个样本，P99 等于样本最大值，不提供稳健尾部保证。
