# 递归解析器身份认证：RQ1-RQ5实验报告

报告日期：2026-10-10。依据当前Computer Communications论文候选稿及Supplement S1-S6，整理已经完成的实验与已有分析结果。

## 1. 实验目标、平台与计数方式

本研究考察一次递归DNS查询中的解析器身份认证。系统先由执行证据固定该查询的候选解析器声明，再使用独立接纳的身份视图检查密钥、角色、端点及生命周期状态，最后把认证决定应用于对应DNS响应。RQ1-RQ5依次考察候选关联、身份检查、决定绑定、服务依赖和部署成本。

### 平台与处理路径

实验平台分配九个Raspberry Pi角色：客户端、管理端/Wrapper、R1-R3、AuthDNS、Norn A、监测端和评估端；Norn B与R2共用主机。DNS和控制流量经过四个路由器及物理LAN/NAT路径，由一个运营者管理。

完整未命中缓存的D3路径为：客户端 → Wrapper → R1 → R2 → R3 → AuthDNS。D1-D3表示配置的解析器数量；缓存命中时，实际查询链可以提前结束。Rust组件承担登记、观察、证据验证及身份同步，SQLite保留本地状态，Knot执行DNS处理。

### 五组实验的分工

| 实验 | 核心问题 | 已完成规模 |
|---|---|---|
| RQ1 | 哪些候选解析器声明属于该查询？ | 11条件，2,200个测量Root |
| RQ2 | 独立身份政策能否拒绝不合法声明？ | 200次live DNS负向决策、1,500个isolated负向案例；另有正向对照与30次发布事件 |
| RQ3 | 决定能否被换用于别的响应或再次使用？ | 700个本地负向案例、70个正常对照、24,000个组件输入/测试组；另有四个组件接受案例 |
| RQ4 | 依赖服务不可用时，查询和恢复如何表现？ | 302次故障事件；700个独立恢复查询 |
| RQ5 | 认证部署的时延、可靠性及调度效果如何？ | 26条件、130对、260块、30,600个测量请求 |

### 如何理解计数

Root是一次查询执行的身份关联标识；负向案例是对某验证入口的刺激；组件fixtures/groups可能包含共享来源的构造；故障事件包含活动期和恢复过程；RQ5按客户端交换计数。UDP截断后TCP继续可能产生不同Root，但在RQ5中属于一个完成的客户端交换。上述数字不能直接相加。

结果依据包括已有冻结配置、客户端响应、六角色抓包、Context/Trace/Graph记录、身份及Store状态和恢复记录。本报告直接使用既有汇总与表格数值，覆盖的是指定接口、配置和测试条件。

## 2. RQ1：功能行为与候选解析器关联

### 为什么做

缓存、转发、重试和传输回退会改变一次查询涉及的解析器。身份认证需要先确定该查询应检查的候选声明。因此，RQ1检查候选记录能否随DNS行为变化，以及记录的终止位置和选中来源是否满足对应条件。

### 做了什么

每个条件包含100个UDP和100个TCP测量Root；每种传输分为五批，每批20个测量。额外600个缓存准备查询单独计数。下表列出全部11个条件。

| 条件 | 检查内容 | 满足检查的Root |
|---|---|---|
| D1 | 一层解析器配置下的候选与终止关系 | 200/200 |
| D2 | 两层解析器配置下的候选与终止关系 | 200/200 |
| D3 | 三层解析器配置下的候选与终止关系 | 200/200 |
| cache-R1 | R1命中缓存时，候选在R1终止 | 200/200 |
| cache-R2 | R2命中缓存时，候选在R2终止 | 200/200 |
| cache-R3 | R3命中缓存时，候选在R3终止 | 200/200 |
| NXDOMAIN | 正确负向回答及相应执行记录 | 200/200 |
| Retry winner | 首次发送失败后，记录选中的后续操作 | 200/200 |
| Truncation/fallback | UDP截断及TCP继续的行为与关联 | 200/200 |
| Profile B | R1 → R3 → AuthDNS的替代配置路径 | 200/200 |
| Profile A/B switch | 配置切换前后的候选和响应关系 | 200/200 |

重试条件设置问题特定的首个数据报DROP，并核对一个Attempt内不同Hop、超时后再次发送及Graph选择的最终操作。配置切换保留了10份明确切换记录。网络抓包观察传输、丢失及fallback，Producer/Adapter事件提供本地来源关系，用于与Graph和客户端响应核对。

### 结果与解释

全部2,200个测量Root满足各自功能检查。结果支持当前实现对已测试深度、当前缓存终止、可区分重试、传输回退和固定配置变化的记录能力。

抓包和DROP计数提供Graph之外的网络观察；内部winner参照仍使用参与Graph构建的Producer关系，存在共享错误风险。缓存实验检查当前回答终止点，没有恢复历史缓存填充路径。任意动态多上游选择及对抗性同摘要、迟到报文的完整归属尚未由这组实验建立。

## 3. RQ2：身份认证与身份状态变化

### 为什么做

已撤销或停用的解析器可能仍被旧转发配置选中。RQ2检查独立身份视图能否拒绝该候选中的不合法身份，并分别检查密钥、角色、端点、快照和终端政策。正向对照用于确认对应入口仍接受合法输入。

### 做了什么及结果

17个负向条件各有100个案例。前两类为真实DNS决策，各含50个UDP和50个TCP请求，共200次；其余15类共1,500个案例，调用隔离的生产验证函数。

| 测试入口 | 条件 | 结果 |
|---|---|---|
| Live DNS | revoked-R2、inactive-R2：旧转发仍可达，候选包含不被接受的R2声明 | 各100/100身份拒绝 |
| Snapshot/Store | 无效签名、签名有效但schema不合法、过期快照、运行期回滚、重启后回滚、同高度冲突 | 每类100/100拒绝 |
| Wrapper identity join | 未知身份、错误角色、错误DNS端点、错误Agent端点、换钥后使用旧钥 | 每类100/100拒绝 |
| Identity signature | wrong-key | 100/100拒绝 |
| Graph/Wrapper policy | 嵌入式替代Registry、错误终端角色、未授权外部边界 | 每类100/100拒绝 |

五类identity-join报告各保留100个合法基线接受；wrong-key入口保留一个接受基线，快照及Graph/Wrapper入口保留各自正常控制。错误角色和旧钥候选还具有记录中的有效身份对象签名，说明签名通过与政策属性被接受是不同检查。

另有30次撤销/重新激活发布事件，15次UDP、15次TCP，记录了30次身份拒绝和30次恢复正常放行。以下时间保持原有观察口径，单位为秒。

| 发布到观察节点 | 中位数 | P95 |
|---|---|---|
| 撤销：双节点观察 | 31.69 | 34.55 |
| 撤销：accepted view被观察到 | 56.36 | 60.46 |
| 撤销：首次观察到查询拒绝 | 64.31 | 69.77 |
| 重新激活：双节点观察 | 31.16 | 34.03 |
| 重新激活：accepted view被观察到 | 56.24 | 59.13 |
| 重新激活：首次恢复放行 | 63.00 | 65.85 |

### 结果意味着什么

RQ2支持指定入口的身份政策拒绝、合法输入控制和状态恢复。200次live与1,500个isolated案例保持入口区别；wrong-key单项结果没有独立验证完整历史公钥传递链。

查询固定的旧视图在新视图到达后仍可能通过freshness及其他检查。双节点/视图时间含控制端单调时钟轮询延迟；首次拒绝/恢复跨主机墙钟、缺少校准偏差界限。上述时间不保证即时全局撤销。

## 4. RQ3：响应绑定与授权非复用

### 为什么做

身份接受之后，认证决定还需约束同一查询的最终响应。RQ3检查能否替换响应字节、拼接另一查询的记录、变更challenge重复消费，或在持久化消费后通过进程退出/重开获得另一次授权。

### 本地负向案例及正常对照

这些案例由真实DNS执行支撑，并在专用入口调用生产函数。

| 条件 | 被拒绝/负向案例 | 完成的正常对照 | 测试入口 |
|---|---|---|---|
| Held-response替换 | 200/200 | 20/20 | Production emit |
| 更换challenge后再次消费 | 100/100 | 10/10 | Production Store |
| 消费后、发送前退出并重开 | 200/200 | 20/20 | 专用进程及Store |
| Cross-Root替换 | 200/200 | 20/20 | Production Graph validator |

响应替换修改准备后消息的TXID低字节；changed-challenge在原Root已消费后尝试再消费，并保留合法原响应；崩溃案例重开同一Store；cross-Root使用两个真实来源执行构造候选，停在Graph验证入口。700个指定负向案例均被拒绝，70个正常对照完成。

### 组件覆盖与四个接受案例

组件套件包含24个单元，每个1,000个fixtures/groups，共24,000。覆盖消费竞争、响应替换、重放、父/Trace/终端引用、事件乱序或延迟、过期/关闭、同摘要、TXID复用、Context/Hop冲突、多个候选和未选中来源等。一些构造共享来源Graph，计数单位不是独立物理查询。

另有四个较早的多签名方pilot构造，原期望拒绝但实际被Graph组件接受，保持如下结果。

| 构造 | 数量 | 所需签名权限 | 观察结果 |
|---|---|---|---|
| Cross-trace UDP/TCP | 2 | R2边、R3目标证明、R1外层Graph | 共同替换引用并重签后被接受 |
| Terminal-swap UDP/TCP | 2 | R3边、AuthDNS目标证明、R1外层Graph | 共同替换终端事件并重签后被接受 |

该组件检查签名及引用一致性，没有独立读取原观察历史来确认替换事件是否发生。其入口未执行Wrapper独立身份join、Root消费及发送，因此接受结果尚未展示客户端可见绕过。它们需要共同签署改变的历史记录，超出A3忠实本地观察的前提；后来的不同刺激拒绝没有修复原四个构造。

### 结果意味着什么

已完成部分支持指定入口的精确响应字节检查、Root非复用及消费状态跨重开保持。changed-challenge拒绝支持Root级非复用，没有验证challenge生成或全部新鲜性。原3,200例物理计划完成700例，另2,500例未执行；同步物理组为0/600，消融对为0/4,000。

## 5. RQ4：服务依赖、故障表现与恢复

### 为什么做

证据生成、Agent控制路径和独立身份后台具有不同职责。RQ4通过依赖故障检查当前查询需要哪些在线服务，以及已有身份视图能否支持短时后台不可用，同时观察恢复后的查询服务。

### 做了什么及结果

六类场景各50次事件，包含25次UDP与25次TCP；有效缓存下Registry Sync场景完成两次，每种传输一次。SR表示有明确证据的拒绝，EC表示预期继续，INC表示不确定结果。

| 不可用组件/场景 | 事件数 | SR | EC | INC | 恢复查询 |
|---|---|---|---|---|---|
| R1 Agent | 50 | 50 | 0 | 0 | 100/100 |
| 选中的下游Agent | 50 | 1 | 0 | 49 | 100/100 |
| Trace Producer | 50 | 50 | 0 | 0 | 100/100 |
| Trace Adapter | 50 | 50 | 0 | 0 | 100/100 |
| Norn A，新鲜视图 | 50 | 0 | 50 | 0 | 100/100 |
| Norn B，新鲜视图 | 50 | 0 | 50 | 0 | 100/100 |
| Registry Sync，有效缓存 | 2 | 0 | 2 | 0 | 100/100 |

302次活动期事件中，151次明确拒绝、102次预期继续、49次下游Agent活动不确定超时。恢复查询来自七个独立最终块，共700个查询成功，保持与活动期事件的计数区别。

### 如何解释依赖与超时

Agent、Producer或Adapter故障约束新查询的证据和登记路径；已接纳且仍可用的身份视图支持了短时Norn故障中的查询继续。两个Registry Sync继续案例使用generation 104，其存储时间参数距固定心跳分别4秒和21秒，没有跨越身份视图过期边界。

49次不确定超时均观察到R1 TRACE_BOUND和CLIENT_QUERY记录，其中16次还有REGISTERED子Context。活动快照没有匹配的完整Graph、Wrapper proof、Root authorization或正常emit记录；现有材料未确定具体阻塞RPC、队列或等待点。这49次保持INC分类，恢复成功也不能补出缺失的活动期结论。

### 结果意味着什么

实验区分了逐查询证据依赖与可保留身份状态的依赖，展示了对应场景下的拒绝、继续服务和恢复能力。其余48次Registry计划事件未执行；过期视图故障、一般可用性率和恢复时延分布尚未建立。Episode PASS仅代表完成注入/恢复流程，不能替代每次活动期的SR/EC/INC结果。

## 6. RQ5：比较设计、工作负载与指标

### 为什么做

身份认证增加登记、证据处理、身份验证和响应授权步骤。RQ5量化完整认证部署的服务代价，并检查重叠登记I/O是否改善时延。比较包括22个native/pipelined条件和4个serial/pipelined条件，分别回答部署成本与调度效果问题。

Native入口是非缓存Knot转发器，下游使用原生Knot及私有缓存；认证部署使用Wrapper、instrumented Knot、Producer/Adapter、Agent和证据放行路径。Serial完成本地登记后启动目标RPC；pipelined并行启动后汇合相同的必要检查。Native比较反映部署整体变化。

### 26个条件的组成

| 条件组 | 内容 | 条件数 |
|---|---|---|
| D3常规 | UDP/TCP各覆盖hot、cold、mixed、NXDOMAIN；另有UDP near和fallback | 10 |
| Serial/pipelined | D3、UDP/TCP、hot/cold | 4 |
| 深度比较 | D1/D2、UDP、hot/cold | 4 |
| 速率扫描 | D3、UDP、hot/cold、0.25/0.5/1/2 QPS | 8 |

每个条件五对重复，每对含A/B两个块，共130对、260块。每块60秒预热、120秒提供测量请求、额外180秒固定排空等待。正式测量30,600个请求，预热15,300个请求；primes及其他控制单独计数。AB/BA顺序总体65/65，为确定性平衡顺序。

### 缓存与回答条件

Hot/mixed有独立成功prime，mixed为80% hot；每种模式进行缓存准备/重置。Cold测量名称在块内不重复，与预热集合分离。Near要求未截断的900-1,232字节TXT响应；fallback要求UDP TC后完成TCP继续。客户端EDNS payload为1,232、DO=false，解析器侧DNSSEC验证仍启用。

Valid answer表示完成客户端交换并满足记录的响应码及工作负载条件。正确NXDOMAIN计成功，SERVFAIL/超时计失败；该指标是工作负载结果分类。

### 指标与重复单位

可靠性为有效测量回答/全部提供的测量请求。成功时延从客户端交换任务开始计至最终结果，包含必要fallback、排除dispatch lag。P50为样本中位数，P95/P99为nearest rank；表值为可用块分位数的中位数。零成功块的时延未定义。

成对倍率对每对的块P50计算B/A，再对这些比值取几何平均。五对是重复单位；near只有四对可定义时延、五个可靠性观察。已有4/5对经验bootstrap区间描述该测试平台内的重复变动；分析为事后探索，确定性次序不是随机分配。

## 7. RQ5：主要结果与服务代价

### 原生与流水线认证部署

下表列出默认1 QPS下D3 hot/cold主要结果。时延列是块P50的中位数；成对倍率另由每对比值的几何平均得到。该批次的native每行均为600/600有效回答。

| 条件 | Native P50/ms | Pipelined P50/ms | 成对P50 B/A | B有效/提供 |
|---|---|---|---|---|
| UDP hot | 31.69 | 210.29 | 6.99 | 599/600 |
| UDP cold | 101.93 | 919.74 | 9.17 | 599/600 |
| TCP hot | 39.78 | 239.85 | 5.95 | 600/600 |
| TCP cold | 106.58 | 964.31 | 9.08 | 600/600 |

认证部署的主要D3成功回答P50倍率为5.95-9.17。以UDP cold为例，101.93/919.74 ms是表列汇总，9.17来自配对估计，不能用表列中位数相除替代。现有结果没有分离签名、TLS或单个阶段的成本。

Cold流水线P50汇总随配置深度从D1的355.43 ms、D2的635.35 ms增加至D3的919.74 ms。独立2 QPS cold扫描点两模式均为1,197/1,200，native/pipelined P50为90.99/1,241.50 ms，尚未定位容量上限。

### 串行与流水线调度

下表使用独立于上表的配对批次，包括不同的pipelined样本。比值小于1表示该成对估计偏向流水线较低时延。

| 条件 | 成对P50 pipelined/serial | 描述性区间 |
|---|---|---|
| UDP hot | 1.071 | [0.992, 1.198] |

### 可靠性与near观察

Near pair044的120个正式测量均返回本地SERVFAIL，块结果为0/120；条件汇总为480/600 pipelined，对应native为600/600。日志和抓包将失败定位到入口Root登记请求、成功ACK和DNS发送之前；底层RPC、TLS、网络或队列原因仍未知，大响应与欠压没有被确定为根因。

失败块不具有可定义的成功时延，near倍率7.59使用其余四对；五个可靠性块均保留。全部测量失败为133个（10个超时、123个SERVFAIL），另有330个预热失败。既有B1成功计数17,570包括2,398 serial及15,172 pipelined，不替代全部请求分母。

## 9. 已支持的结论、完成范围与材料依据

### 五组结果如何共同支撑研究

RQ1说明候选记录在指定DNS行为下满足功能关联检查。RQ2提供独立身份政策在真实查询及指定验证入口的直接拒绝与接受控制。RQ3约束认证决定与响应字节、Root消费及持久状态的关系。RQ4展示逐查询证据和身份状态依赖的不同故障表现。RQ5量化部署成本与可靠性，并观察调度效果。

这些证据共同支持查询特定的候选身份检查和对应响应决定。A1-A4及现有Theorem 1仍给出正常放行的必要条件；RecordClosed/RecordBound不能直接推出所有真实远端参与者已被认证。一般远端发送到目标到达的归属仍未建立，也未展示客户端可见绕过。
